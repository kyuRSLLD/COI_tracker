# Private-file UI: synthetic-only browser harness

`client/src/v2/PrivateFiles.tsx` exports an unmounted `PrivateFiles` component. Supply an auth-v2 subcontractor bearer token as the `token` prop in memory. `maxFileBytes` may be a trusted, lower server limit (default and absolute ceiling 10 MiB). The host must replace/clear the token on session changes and provide a reviewed authenticated environment. There is no integration into production or legacy pages.

The component uses fixed same-origin `/api/v2/self-reported-private-files` paths and, for its selectors, the staged `/api/v2/self-reported-coi-metadata/own` and `/connected-gcs` endpoints. It uploads the selected `File` directly with its MIME type, not multipart. Its file selector is populated only from the owner ready-file listing; pagination uses `POST` with `after`. The server is authoritative for ownership, file scanning, GC connection, size and all grants. The API has no owner grant listing, so the UI does not claim current grant status. A canceled or failed upload may have succeeded, and a retry makes a new file. A canceled/failed grant or revoke may also have succeeded. Refresh the list before retrying uploads; already delivered bytes cannot be recalled.

Preview fetches only the authenticated owner endpoint, checks type and bounded length, and renders only supported images or a sandboxed PDF iframe using a temporary blob URL. URLs are revoked on close, replacement, refresh, session switch and unmount. Scanning is not insurance verification, sanitation or a safety guarantee; sandboxing does not make document rendering risk-free. No storage URL is exposed. The component and host should be reviewed with a restrictive CSP and browser PDF-renderer policy before any real deployment.

Run `python3 client/tests/v2-private-files/test_private_files.py` from the repository root with workspace dependencies, Python Playwright and `/usr/bin/chromium` installed. The harness starts Vite locally and intercepts every API call with synthetic fixtures; external browser requests are blocked. It does not test a live router, real scanner, storage, identity, authorization, browser PDF sandbox internals, or deployment readiness. The staged backend is default-off and is not production-mounted.

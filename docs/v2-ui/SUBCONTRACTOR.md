# Standalone subcontractor workflow (v2)

This is an unmounted React component, not integrated with the legacy application or server. The host supplies a short-lived authenticated subcontractor access token via `<SubcontractorWorkflow token={accessToken} />`; import from `client/src/v2/SubcontractorWorkflow`. Never hardcode credentials in a real host. The component holds capabilities only in React memory; a token change unmounts/reset state. Requests use same-origin paths, a Bearer header, no cookies, redirects, cache, query strings or external QR services. The hosting application is responsible for a secure origin, authentication/session lifecycle, CSP, redaction of request/response bodies and credentials by infrastructure, and ensuring only the intended v2 routers are mounted. Treat the QR as a bearer secret; closing or hiding the page does not revoke a server-issued QR. A page refresh can lose track of an issued QR without invalidating it.

Contracts: `docs/GC_SUB_CONNECTIONS_V2_ROUTER.md` and `docs/SELF_REPORTED_COI_METADATA_V2.md` in the source worktree. At the time this work was based on `a378622`, the second document and implementation were untracked in that source worktree, so they are not automatically part of this isolated worktree. Both endpoints are synthetic-only prototypes and require separate integration, security review and operational safeguards; this UI does not make them production-ready.

## Calls and semantics

- `GET /api/v2/connections/profile` → `{profileId,evidenceType}`; `GET /consent` → `{version,qrText,invitationText}`. The UI renders `qrText` unchanged and requires a separate unchecked checkbox before `POST /qr` with exactly `{profileId,consentVersion,affirmative:true}`. The response `{token,expiresAt}` is used directly as the SVG QR payload—not a URL. Only explicit clicks issue a QR, with a synchronous in-flight guard, no automatic retry and no new QR while the displayed one is active. An unconfirmed outcome is blocked for five minutes in this mounted instance; a reload cannot preserve that guard. The server's expiry and one-use rules are authoritative and redemption status is not exposed to this UI.
- `GET /api/v2/self-reported-coi-metadata/own` → `{records:[...]}` with `effective_date`, `expiration_date`, and `coverage[{type,limitCents}]`; `POST /own` → `{id}` with exactly `{carrier,effectiveDate,expirationDate,coverage}`. Each correction is a new record. UI validates dates, unique coverage labels, and cents within documented limits; server validation remains authoritative.
- `GET /connected-gcs` → `{generalContractors:[{gc_user_id,gc_name}]}`; `GET /consent` → `{version,text}`. With a selected record and connected account shown alongside the exact server text, a new unchecked affirmative checkbox enables `POST /grant` with `{coiId,gcUserId,consentVersion,affirmative:true}`. `POST /revoke` with `{coiId,gcUserId}` revokes that pair, idempotently. The API exposes no owner-side grant listing; this UI does not invent one or claim current grant state. Its connected GC account list is not proof of identity or authority.

A profile connection alone shares no COI metadata or files; the separate metadata grant shares no file, future record or client access. Revocation cannot retract information already seen. File upload/access is explicitly unavailable. No invitation, profile editing, connection revocation, or GC-facing workflow is implemented. A user may need the separate connection-revocation flow to disconnect a GC or invalidate outstanding QRs. All displayed personal/business/insurance information is self-reported and insurance is unverified.

## Test

`python3 client/tests/v2-sub/test_sub.py` starts an ephemeral loopback Vite process, intercepts all API requests with synthetic fixtures, blocks off-origin requests, and requires Python Playwright, Chromium, Pillow, and system `libzbar`. No production API, server, or credentials are used. The `client/tests/v2-sub/index.html` harness is for this test only; it cannot operate against live APIs with its synthetic token. The normal frontend build is `npm run build --workspace=client`. To independently bundle the disconnected harness: `./node_modules/.bin/vite build --config client/tests/v2-sub/vite.config.ts --outDir /tmp/coi-sub-v2-standalone-build --emptyOutDir`.
